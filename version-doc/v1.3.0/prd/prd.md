## 一、背景与目标

当前 Agency Agents Platform 缺乏用户反馈机制，用户无法了解其他人对 Agent 的使用体验。增加评分评价功能可以帮助用户快速筛选优质 Agent，同时为 Agent 创建者提供改进方向。

**产品目标**：构建完整的 Agent 评分评价体系，让用户能够对 Agent 进行评分和评价，并通过评分排序帮助其他用户发现优质 Agent。

**成功指标**：
- 上线后 1 周内，至少 30% 的活跃用户对 Agent 进行过评分
- Agent 列表页的平均停留时间提升 15%（用户通过评分筛选更高效）

## 三、功能模块详情

### 功能模块 1：Agent 评分评价（提交）

> 来源：BRD 需求 1, 2
> 优先级：P0

#### 1.1 功能描述

已登录用户可以在 Agent 详情页对 Agent 进行 1-5 星评分，并可选地撰写文字评价（限 500 字）。每个用户对同一 Agent 只能有一条评分评价记录，但可以修改。

#### 1.2 用户故事

作为 已登录用户，我希望 在使用 Agent 后给它打分和写评价，以便 帮助其他用户了解 Agent 的质量。

#### 1.3 交互流程

**主流程（新增评分）**：
1. 用户进入 Agent 详情页（`/agents/:slug`）
2. 在评价区域看到星星评分组件（默认未选中）
3. 点击星星选择 1-5 分
4. 可选：在文本框中输入评价内容（限 500 字，实时显示剩余字数）
5. 点击"提交评价"按钮
6. 提交成功 → 显示成功提示，评价出现在列表顶部
7. 提交失败 → 显示错误提示

**修改评分**：
1. 如果用户已评价过，评分区域显示已有评分和评价内容
2. 用户可以修改星星评分或编辑评价文字
3. 点击"更新评价" → 更新成功提示

**删除评价**：
1. 用户点击自己评价旁的"删除"按钮
2. 弹出确认对话框
3. 确认删除 → 评价从列表中移除

**异常流程**：
1. 未登录用户 → 评分区域显示"请先登录后评价"，点击跳转登录
2. 评价内容超过 500 字 → 输入框禁止继续输入，提示"评价内容不能超过 500 字"

#### 1.4 接口约定

| 接口 | 方法 | 路径 | 说明 | 状态 |
|------|------|------|------|------|
| 提交/更新评价 | POST | /api/agents/:slug/reviews | 创建或更新评价（upsert） | 新增 |
| 删除评价 | DELETE | /api/agents/:slug/reviews | 删除当前用户的评价 | 新增 |
| 获取我的评价 | GET | /api/agents/:slug/reviews/mine | 获取当前用户对该 Agent 的评价 | 新增 |

#### 1.5 数据模型约定

**AgentReview（新增）**：

| 字段 | 类型 | 必填 | 说明 | 状态 |
|------|------|------|------|------|
| agentSlug | string | ✅ | 关联的 Agent slug | 新增 |
| userId | ObjectId | ✅ | 评价用户 ID | 新增 |
| username | string | ✅ | 评价用户名（冗余，避免联表） | 新增 |
| rating | number | ✅ | 评分 1-5 | 新增 |
| content | string | 否 | 评价内容，限 500 字 | 新增 |
| createdAt | Date | ✅ | 创建时间 | 新增 |
| updatedAt | Date | ✅ | 更新时间 | 新增 |

**索引**：
- `{ agentSlug: 1, userId: 1 }` — 唯一索引，确保一人一评
- `{ agentSlug: 1, createdAt: -1 }` — 按时间倒序查询

**Agent Model（修改现有）**：

| 字段 | 类型 | 必填 | 说明 | 状态 |
|------|------|------|------|------|
| ratingStats.avgRating | number | 否 | 平均评分（保留一位小数） | 新增字段 |
| ratingStats.totalReviews | number | 否 | 评价总数 | 新增字段 |
| ratingStats.distribution | number[] | 否 | 各星级数量 [1星数, 2星数, 3星数, 4星数, 5星数] | 新增字段 |

#### 1.6 页面设计

**AgentDetailPage（修改现有）**：
- 路由：/agents/:slug
- 在现有详情内容下方新增"评分评价"区域
- 评分输入：Antd `Rate` 组件（5 星）
- 评价输入：Antd `Input.TextArea`（maxLength=500，showCount）
- 提交按钮：Antd `Button`（type="primary"）
- 复用组件：`Rate`（Antd）、`Input.TextArea`（Antd）、`Button`（Antd）

#### 1.7 验收标准

**正向场景**：
- [ ] 已登录用户可以对 Agent 打 1-5 星评分
- [ ] 已登录用户可以撰写评价内容（可选）
- [ ] 提交成功后显示成功提示
- [ ] 用户可以修改自己的评分和评价
- [ ] 用户可以删除自己的评价

**异常场景**：
- [ ] 未登录用户看到"请先登录后评价"提示
- [ ] 评价内容超过 500 字时禁止输入
- [ ] 未选择评分直接提交时提示"请先选择评分"
- [ ] 网络错误时显示错误提示

**权限场景**：
- [ ] 用户只能修改/删除自己的评价
- [ ] 每个用户对同一 Agent 只能有一条评价

### 功能模块 2：评分评价展示

> 来源：BRD 需求 3
> 优先级：P1

#### 2.1 功能描述

Agent 详情页展示评分统计信息（平均分、评分人数、各星级分布柱状图）和评价列表（按时间倒序，支持分页）。

#### 2.2 用户故事

作为 普通用户，我希望 查看其他人对 Agent 的评分和评价，以便 决定是否使用该 Agent。

#### 2.3 交互流程

**主流程**：
1. 用户进入 Agent 详情页
2. 评价区域顶部显示评分统计：
   - 左侧：大号平均分数字 + 星星图标 + "N 人评价"
   - 右侧：各星级分布条形图（5 星 → 1 星，每行显示百分比）
3. 下方显示评价列表：
   - 每条评价：用户名 + 评分星星 + 评价内容 + 时间
   - 按时间倒序排列
   - 底部分页器（每页 10 条）

**空状态**：
1. 无评价时显示"暂无评价，成为第一个评价者吧！"

#### 2.4 接口约定

| 接口 | 方法 | 路径 | 说明 | 状态 |
|------|------|------|------|------|
| 获取评价列表 | GET | /api/agents/:slug/reviews | 分页获取评价列表 + 统计信息 | 新增 |

**请求参数**：

| 参数 | 位置 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| page | query | number | 否 | 页码，默认 1 |
| limit | query | number | 否 | 每页条数，默认 10 |

**响应 Body**：

```json
{
  "success": true,
  "data": {
    "stats": {
      "avgRating": 4.2,
      "totalReviews": 56,
      "distribution": [2, 3, 8, 15, 28]
    },
    "reviews": [
      {
        "_id": "...",
        "userId": "...",
        "username": "user1",
        "rating": 5,
        "content": "非常好用！",
        "createdAt": "2026-04-14T10:00:00Z"
      }
    ]
  },
  "pagination": { "page": 1, "limit": 10, "total": 56, "pages": 6 }
}
```

#### 2.5 页面设计

**AgentDetailPage（修改现有）**：
- 评分统计区域：使用 Antd `Rate`（disabled）+ `Progress` 组件展示分布
- 评价列表：使用 Antd `List` + `Pagination` 组件
- 新增组件：`ReviewStats`（评分统计展示）、`ReviewList`（评价列表）

#### 2.6 验收标准

**正向场景**：
- [ ] 详情页显示平均评分（保留一位小数）
- [ ] 详情页显示评分人数
- [ ] 详情页显示各星级的评分分布
- [ ] 评价列表按时间倒序排列
- [ ] 评价列表支持分页（每页 10 条）

**边界条件**：
- [ ] 无评价时显示空状态提示
- [ ] 只有 1 条评价时正确显示统计信息

### 功能模块 3：列表页评分排序

> 来源：BRD 需求 4
> 优先级：P1

#### 3.1 功能描述

Agent 列表页的每个 Agent 卡片上显示平均评分（星星图标 + 数字），列表支持按评分从高到低排序。

#### 3.2 用户故事

作为 普通用户，我希望 在 Agent 列表页看到评分并按评分排序，以便 快速找到高质量的 Agent。

#### 3.3 交互流程

**主流程**：
1. Agent 列表页每个卡片右下角显示：⭐ 4.2（56）
2. 列表顶部排序下拉框新增"按评分排序"选项
3. 选择"按评分排序" → 列表按平均评分从高到低重新排列
4. 无评分的 Agent 排在最后

#### 3.4 接口约定

| 接口 | 方法 | 路径 | 说明 | 状态 |
|------|------|------|------|------|
| 获取 Agent 列表 | GET | /api/agents | 增加 sort=rating 查询参数 | 修改现有 |

**新增请求参数**：

| 参数 | 位置 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| sort | query | string | 否 | 排序方式：`rating`（按评分降序） |

#### 3.5 页面设计

**AgentsPage（修改现有）**：
- Agent 卡片新增评分显示（Antd `Rate` 小尺寸 disabled + 数字 + 评价数）
- 排序下拉框新增"按评分排序"选项

#### 3.6 验收标准

**正向场景**：
- [ ] Agent 卡片显示平均评分（星星 + 数字）
- [ ] Agent 卡片显示评价数量
- [ ] 列表支持按评分排序（从高到低）

**边界条件**：
- [ ] 无评分的 Agent 显示"暂无评分"
- [ ] 按评分排序时，无评分的 Agent 排在最后

## 四、非功能需求

### 4.1 性能要求

| 场景 | 指标 | 目标值 |
|------|------|--------|
| 评价列表加载 | 首屏加载时间 | < 500ms |
| 提交评价 | 响应时间 | < 1s |
| Agent 列表按评分排序 | 响应时间 | < 500ms |

### 4.2 安全要求

- 评分提交需要 `requireAuth` 认证中间件
- 用户只能修改/删除自己的评价（后端校验 userId）
- 评价内容需要 XSS 过滤（前端 escape + 后端 sanitize）
- 评分值后端校验范围 1-5（整数）

### 4.3 兼容性要求

- 评分星星组件在移动端可点击

### 4.4 可用性要求

- 评价列表需支持：加载状态（Skeleton）、空状态、错误状态
- 提交评价需支持：提交中状态（按钮 loading）、成功/失败提示
- 评分统计需支持：数据加载中的 Skeleton 占位
